## Findings (snapshot, unverified against current branch)
- **F175 P1 — visual evidence screenshot filename collisions.** `visual_outreach_evidence_strict_cli.py:397–436` constructs folders from result rank + sanitized business name, and timestamps only to seconds for temporary/output locations. Duplicate ranks/names or runs in the same second can reuse path and override evidence; use immutable run UUID and per-business source identity.
- **F176 P1 — browser route blocking is DNS lookup not connection pinning.** `visual_outreach_evidence_strict_cli.py:135–155` uses domain resolution to approve `route.continue_()`; browser separately resolves the host later. DNS rebinding between preflight and network connection cannot be excluded by policy; compare with `collector.py` pinned-IP strategy before claiming SSRF-grade safety. Scope to sites the operator explicitly requests; do not browse unknown internal destinations.
- **F177 P2 — review intelligence extractor suppresses DOM errors.** `review_intelligence_cli.py:150–200`, `review_intelligence_hardened_cli.py:59–266`, `review_intelligence_sampling_safe_cli.py` frequently ignore Playwright selector errors and interpret no results as missing labels/reviews. Manifests include explicit failures at larger boundaries, but per-field completeness needs provenance status (`observed`, `not_available`, `error`).
- **F178 P2 — review collectors duplicate scroll/sampling logic.** `review_intelligence_cli.py`, `review_intelligence_hardened_cli.py`, `review_intelligence_sampling_safe_cli.py` implement similar fallback extraction separately. Changes to Google's DOM may fix one path but not others. Common immutable extraction primitives and fixture-based selector contracts would reduce divergence; preserve method-specific sample provenance.
- **F179 P1 — multiple visual outreach engines duplicate risky browser policy.** `visual_outreach_evidence_cli.py`, `visual_outreach_evidence_strict_cli.py`, `visual_outreach_hardened_cli.py`, `visual_outreach_regulatory_cli.py` each contain browser setup, route validation, screenshots and ZIP writing. Consolidate after establishing a canonical outcome, since differing policy lets an unsafe URL rejected in one path be attempted in another.
- **F180 P2 — visual regulatory summary is evidence-dependent, not legal advice.** `visual_outreach_regulatory_cli.py:181–207` emits claimed maxima/practical exposure from source payload; no law lookup/citation validation at generation time. Clearly label unverified regulatory claims, do not turn them into direct prospect allegations.
- **F181 P2 — retired SaaS session API should stay unmounted.** `session_api.py` handles legacy session actions, `public_web.py` old public tooling; compare runtime route inventory/CLI before code retirement. Preserve old identity schema and backups.
- **F182 P2 — mutable generated ZIP/sidecar output is not transactional.** `visual_outreach_hardened_cli.py:318–332`, `visual_outreach_regulatory_cli.py:244–249` write manifest/evidence/HTML then zip. Interruption can leave partial intermediate sidecars that another invocation could misread. Use temp run directory + complete atomic output publication.

## Positive controls
- Review intelligence captures failure diagnostics per business and differentiates selected sampling strategies in output.
- Visual strict routes abort private/reserved hosts before requests where DNS already resolves to non-public IPs; HTML summary escapes names, issue descriptions and URLs.
- `visual_outreach_regulatory_cli.py` does not automatically contact prospects, and source evidence is retained in ZIP.
- `tenant_offboarding_cli.py` requires explicit action flags and confirmation checks; do not delete/alter real tenant data.
