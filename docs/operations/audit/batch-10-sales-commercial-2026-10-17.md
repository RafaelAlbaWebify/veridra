## Findings — historical ZIP; remote confirmation required
- **F63 P1 — Duplicate implementations of proposal state transitions.** `agency_deal_web.py:364-445` contains a proposal transition route with customer-creation side effects, while `agency_proposal_transition_web.py:174-251` implements a separately guarded strict transition for the same business domain. Route reachability and router inclusion must be checked before deciding which path is canonical; duplicated semantics risk inconsistency. **Do not delete either until traced from `runtime.py` and templates.**
- **F64 P1 — Deal and prospect update are separate writes.** `agency_reply_transition_web.py:69-147` persists reply/deal first and then prospect status; failure on second write leaves inconsistent stages. Similar `agency_deal_web.py:216-258`, `320-361`. Reconcile with F15/F57 via transactional work item.
- **F65 P1 — Retention preview is not an execution precondition.** `commercial_ops.py:210-250` computes lead/event IDs at preview time; `apply_retention` later deletes IDs without checking their latest status or timestamps. A lead revised after preview could be removed contrary to current retention conditions. Add policy/version recheck and auditable dry-run at commit time; preserve legal retention.
- **F66 P2 — Retention reports success despite failed deletions.** `commercial_ops.py:234-250` suppresses individual `LeadStoreError` and returns original `RetentionPreview`. Callers may assume all candidates were removed. Return actual completed/failed counts and reasons.
- **F67 P2 — Engagement event listing skips corrupted event JSON silently.** `commercial_ops.py:157-174` suppresses read/parse errors; engagement metrics then omit evidence without alerting the operator. Compare with F21/F53. Do not delete corrupt files.
- **F68 P2 — Engagement link creation uses non-atomic direct write.** `commercial_ops.py:103-114` calls `write_bytes` after an existence check without temp/replace, risking truncated token document on write interruption; and link has deterministic hash, so retry may refuse to rewrite a damaged file.
- **F69 P2 — Eligibility importer drops bad items silently.** `commercial_eligibility.py:30-70` skips invalid records and statuses without capturing malformed-entry counts; decision gating then may use default bands. Report validation quality, and distinguish missing eligibility from explicitly eligible.
