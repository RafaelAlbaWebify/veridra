## Findings (new IDs, historical ZIP)
- **F142 P1:** `tenant_bound_lead_capture.py:249-365` saves assessment, charges audit/page reservations, then validates and saves the lead. If lead validation or save fails, assessment plus metered audit may remain while lead usage is released. Clarify “charge per assessment” versus “charge per successful lead” semantics and implement a resumable/compensating journal as appropriate. Risk, not automatically a quota bug.
- **F143 P1:** `tenant_bound_lead_capture.py:297-365` writes assessment, two usage records, lead, then a third usage record as separate steps. Failure between writes produces partial state and potential double-charge on form retry. Add idempotency key tied to submission/assessment, with rollback policy. Related F41/F78.
- **F144 P1:** `agency_prospect_web.py:559-565` uses a broad `TenantProspectStoreError` catch to treat any failed load as “not found” and create a new prospect. Corrupt existing prospect JSON or disk errors may be incorrectly interpreted as absence; related F17.
- **F145 P1:** `agency_prospect_web.py:802-829` saves assessment, then updates prospect, then appends activity. Failure after assessment save leaves unlinked evidence; failure after prospect update leaves missing activity. Requires idempotent staged transaction/reconciler, not extra catch-and-ignore code.
- **F146 P2:** `agency_prospect_web.py:484-499` multi-select “prepare prospects” silently skips all store load exceptions and commits one at a time; the user receives no skipped/processed count or durable resume ledger. Distinguish absent from corrupt, report partial outcome.
- **F147 P2:** `agency_prospect_web.py:1038-1058` checks suppression only for first transition to `contacted` when compliance timestamp absent, rather than every transition to contact-related states; ensure suppressed contact never advances through `responded`/`conversation` via UI/API paths without a current consent/legal basis. Policy-level review; don't claim real unlawful outreach.
- **F148 P2:** `tenant_history_api.py:148-162` supports deletion of individual assessments after tenant project access, but other records may reference assessment IDs (AI review, delivery approvals, remediation tasks). Cross-reference deletion with dependent evidence; enforce retention policies and referential safeguards.
- **F149 P2:** `tenant_lead_form_api.py:73-102` returns 404 for all storage-layer failures; corrupted JSON and disk write issues can be masked. Link repair strategy to F140, avoid incompatible per-router mapping.

Good controls: public embedded capture requires consent, origin validation and rate-limiting; binding and entitlement gates before tenant-scoped capture; rejects deep crawl profiles; releases quota reservations on early assessment failure; validates saved lead; reports result as not a penetration test. `agency_prospect_web` enforces qualification gate and explicit outreach eligibility. `agency_ui` supplies shared UI styling and help tips; it is a dependency, not legacy simply because it is mostly static.
