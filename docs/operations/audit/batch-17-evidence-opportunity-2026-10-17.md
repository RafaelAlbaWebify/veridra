## New findings (ZIP baseline)
- **F113 P1 — Suppression storage corruption can defeat the suppression lookup.** `outreach_suppression.py:61-64` uses `path.is_file()` to return suppressed. This conservative behavior remains safe for an existing damaged file; however `load():88-103` returns `None` for corrupt file, which a caller treating as “not suppressed” could misinterpret. Verify all call sites use `is_suppressed` for the mandatory gate, and surface corrupt-record diagnostics.
- **F114 P2 — Suppression reason changes silently replace the previous reason.** `outreach_suppression.py:66-86` replaces the same email-hash file atomically. If suppression reasons are legal/commercial history, prior decisions are overwritten. Consider immutable events + effective current suppression; do not weaken opt-outs.
- **F115 P2 — Verification import silently omits malformed rows.** `website_verification.py:24-64` skips non-dict, nameless, unknown-status records, and later duplicate case-insensitive names overwrite prior verification evidence; the result dictionary has no per-record rejection ledger. An invalid website_found row does raise, so this is not universally silent.
- **F116 P2 — Robots user-agent match is exact-string based.** `robots.py:44-52` prefers groups whose tokens equal the entire supplied agent string; standard robots product-token prefix matching (e.g., `VeridraBot` matching `VeridraBot/1.0`) may be missed if caller supplies full header. Verify actual caller agent format and RFC 9309 compliance before changing behavior.
- **F117 P2 — Opportunity thresholds are heuristic and require market calibration.** `market_opportunity.py:31-131` uses nearest-index quartiles and hardcoded cutoffs. Verified website absence must be independently established; current scoring explicitly marks missing website *observation* as unverified. Preserve that positive safety distinction when tuning.
- **F118 P2 — Observations and HTML-derived evidence are not equivalent to execution.** `observations.py:98-309`, `page_quality.py:76-205`, `finding_value.py:85-206` extract static signals, metadata and typed findings; interpreting them as full DOM or business verification would overstate evidence. This is a reporting contract concern, not evidence that extraction is incorrect.
