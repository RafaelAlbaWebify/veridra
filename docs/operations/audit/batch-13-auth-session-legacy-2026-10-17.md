## Findings, qualified against currently installed routing

- **F85 P2 [legacy candidate, confirmed ZIP runtime wiring]:** `runtime.py` no longer mounts `auth_api`, `browser_auth_web`, `session_api`, or `password_recovery_api`. The hosted account surface is retired for this private Webify runtime, but `password_auth.py`, `password_recovery.py`, password throttles and session lifecycle services remain present and testable. Do **not** simply delete them: their stores and historical identity records can be needed for backup/recovery or compatibility. Trace all CLI and migration entrypoints before classification.
- **F86 P2 [requires race reproduction]:** `login_throttle.py` `record_failure()` reads failure_count and writes later within a connection without an explicit `BEGIN IMMEDIATE` before read. Under concurrent failed logins, events can contend and the count may not represent all attempts (SQLite transaction policy must be checked). Similar concurrency review recommended for `password_recovery_throttle.py`; current runtime does not expose these retired SaaS entrypoints.
- **F87 P2 [maintenance duplication]:** `session_rotation.py` has `rotate_session_atomically()`, while `sqlite_session_manager.py` implements the session rotate transaction and `session_lifecycle.py` calls the latter. Verify uses of both helpers and choose one maintained implementation only after proving exact external/recovery consumers.
- **F88 P2 [positive control / policy validation]:** `password_recovery.py` token issue invalidates prior tokens in the same write transaction; reset consumes token and revokes existing sessions. `session_lifecycle.py` does not accept caller-supplied new tokens. Rotation verifies user/tenant/status before replacing credentials. Preserve these controls if any authentication functionality is retained.
- **F89 P2 [operational caution]:** Changing or deleting these schemas before reconciling the historical SQLite identity database/backup manifests could make archived identity data unreadable. No evidence this has occurred. Schema retention decision belongs to separate migration and backup review.

## Interfaces and status
Historical hosted browser sessions are deliberately absent from normal runtime route inventory; local single-owner identity continues through `application_identity.py` and `identity_middleware.py`. This batch does **not** prove that the authentication code is wholly unused by migration scripts, tests or CLI. No production code altered. Before any changes, compare current branch, inventory all imports and entrypoints, reconcile backups and test concurrent throttle behavior.
