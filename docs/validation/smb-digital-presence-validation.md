# Real-SMB Digital Presence Validation Protocol

Status: ACTIVE / PUBLIC-DATA ONLY / NO OUTREACH
Owner gate: GitHub #297 under #296 and master gate #284.

## Purpose
VERIDRA must prove more than safe deployment. It must prove that Webify Presence Care can identify, explain, prioritize and repeatedly manage digital-presence value for real SMBs with bounded operator time.

Initial validation market: Ireland.
Initial validation vertical: independent dental practices.

## Hard safety and commercial boundary
- REAL OUTREACH COUNT = 0 until #284/#296 are explicitly approved.
- Public observation only.
- Do not submit appointment, medical, payment, lead or contact forms.
- Do not authenticate, modify customer systems, bypass controls, exploit vulnerabilities or probe non-public surfaces.
- Standard dental Presence Care excludes patient/clinical systems and Article 9 health data.
- AI/crawler/readiness observations must not be presented as proof of actual AI visibility.

## Phase A — Cohort
Build 25–50 real Irish dental-practice records with reproducible public provenance.
Prefer independent/SMB practices and small commercially realistic operators. Large chains/groups may be retained only as comparison cases and must be tagged as non-core ICP where appropriate.

Minimum cohort fields:
- business name;
- public website/domain;
- locality/county;
- public business category/sector;
- source/provenance;
- apparent independent/SMB fit state: likely / unclear / non-core;
- review timestamp;
- no-contact flag.

## Phase B — Public digital-presence assessment
Evaluate only evidence that can be reproduced safely from public surfaces.

Assessment dimensions:
1. availability, HTTPS and basic technical health;
2. mobile/responsive usability;
3. broken links and obvious public functional failures;
4. public contact/conversion paths without form submission;
5. technical SEO/indexability/canonical/metadata basics;
6. structured data and local-business signals;
7. trust/public-presence signals;
8. accessibility/basic usability;
9. stale/outdated-content indicators where evidence supports them;
10. passive public security posture within existing VERIDRA boundaries;
11. public local/reputation/review signals only where lawfully observable and reproducible;
12. AI/crawler/readiness only where evidence supports the exact claim.

Each finding must preserve the normal VERIDRA evidence chain:
`observation -> evidence -> affected URL/surface -> business impact -> recommended fix -> service classification -> verification path`.

## Phase C — Human validation
Manually validate a representative 10–15 business subset.

For each finding record:
- validation state: true / false / unverified;
- owner-understandable: yes/no;
- commercially relevant: yes/no;
- Webify-remediable: yes/no;
- Presence Care class: activation / monthly allowance / separate quote / monitor-only / informational / discard;
- operator validation minutes;
- material human-discovered miss, if any.

Aggregate metrics:
- true-positive rate;
- false-positive rate;
- count/rate of material misses;
- owner-understandable rate;
- commercially relevant rate;
- Webify-remediable rate;
- businesses with >=1 credible value opportunity;
- median operator validation time.

No target metric may be silently tuned after results are seen. Weak evidence must be allowed to invalidate or change the offer.

## Phase D — Shadow Presence Care delivery
For 3–5 real businesses, without contact or system changes, complete the internal shadow service:
`baseline -> validated findings -> activation candidate -> remediation/change plan -> customer-grade report -> monitoring configuration -> next-cycle action list`.

Measure:
- active operator minutes;
- useful activation work;
- useful work fitting the 30-minute monthly allowance;
- separately quoted work;
- monitor-only value;
- plausible next-cycle recurring value;
- report clarity/usefulness.

## Phase E — Recurring-value decision
The Ireland €99/month Presence Care recurring model is not validated merely because a website has defects.

Recurring value must be evidenced by a combination of monitoring/regression detection, bounded recurring checks, minor improvements, reporting and customer-relevant follow-up that can be delivered with sustainable operator time.

Possible outcomes:
- VALIDATED: credible recurring value + bounded operator economics;
- CONDITIONAL: value exists but scope/price/cadence needs adjustment;
- NOT VALIDATED: recurring value is too weak or too labor-intensive; revise the offer before outreach.
